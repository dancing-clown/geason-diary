# Rust

## Rust语言核心机制

其实从C++ -> Rust 的话，其实学习曲线没有那么陡峭,区别大致如下。

### 内存模型

#### C++

手动管理裸指针、引用、堆内存；无强制生命周期规则；

风险：野指针、悬垂引用、双重free、数据竞争、UAF；

手段：编码规范、ASAN、代码审查、智能指针，但编译器不强制。

多线程： std::mutex 原子变量，编译器不阻止共享可变引用，写崩全靠自觉。

#### Rust

所有权、借用、生命周期、Send/Sync 静态检查，编译器就杜绝了悬垂引用、数据竞争。

所有权主要是通过移动语义(Move) 转移。例如，将堆数据赋值给新变量或传入函数时，所有权会转移，原变量将失效：

```rust
let s1 = String::from("hello");
let s2 = s1;
// println!("{}", s1); // 错误！s1不再有效。
```

所有权核心规则：

1. 每个值都有一个所有者（变量）；

2. 同一时间只能有一个所有者；

3. 当所有者离开作用域，值将被丢弃（自动释放内存）。

需要注意，对于实现了`Copy` trait 的类型（如整数，布尔值等），赋值时自动复制数据而非移动所有权。

借用允许临时访问数据而不获取所有权，通过引用实现。借用分为两类：

1. 不可变借用(`&T`)：允许多个只读引用同时存在，但在此期间不能有可变引用；
2. 可变引用(`&mut T`)：只允许一个可变引用存在，且在此期间不能有其他任何引用。

```rust
let mut s = String::from("hello");
let r3 = &mut s;
let r1 = &s;
let r2 = &s;
println!("r1: {}, r2: {}", r1, r2); // 使用 r2，r2 保持存活
// println!("r3: {}", r3); // 错误，违反借用规则
```

借用核心规则：

1. 同一时间只能有`一个可变引用`或 `多个不可变引用`；

2. 引用不能超过所有者生命周期；

生命周期主要是确保引用在我们需要的时间内保持有效。大部分情况是隐式推断的。编译器有一个借用检查器，它会比较作用域确定所有借用是否有效。

```rust
fn main() {
    let r;                // ---------+-- 'a
                          //          |
    {                     //          |
        let x = 5;        // -+-- 'b  |
        r = &x;           //  |       |
    }                     // -+       |
                          //          |
    println!("r: {r}");   //          |
}   
```

多线程安全不是文档约定，是类型系统约束；不满足 `Send/Sync` 的类型编译就无法跨线程传递。

`Send` 标记特征表示，实现了该特性的类型的值的所有权可以在线程之间转移。几乎所有Rust类型都实现了该特性`Send`，例外`Rc<T>`类型无法实现Send特征，因为如果克隆后，两个线程可能同时更新引用计数。

`Sync` 标记特性表示，实现了该特性的类型可以被多个线程安全地引用。

除了以上能力，还有比较重要的就是`unsafe Rust`的使用了，包括：

1. 解引用原始指针。

2. 调用不安全的函数或方法。

3. 访问或修改可变静态变量。

4. 实现一个不安全特性。

5. 访问`s`的字段`union`。

需要注意的是，`unsafe` 不会关闭借用检查或禁用Rust的任何其他安全检查。
